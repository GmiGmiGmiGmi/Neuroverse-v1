# Neuroverse v5 — Upload & migration walkthrough

## What I recommend now: GitHub first, not a half-migrated hybrid
Upload the **entire Neuroverse v5 repository to GitHub first**. Keep the site in local mode until the public pages, navigation and content are approved. That gives you one source of truth and a working rollback point.

### 1. Create the GitHub repository
Create a repository such as `Neuroverse` and upload **everything inside this ZIP** to the repository root. Do not upload only the `/docs` folder: the other folders are your future backend/migration assets.

Your GitHub repository should look like:
```
Neuroverse/
  docs/
  supabase/
  scripts/
  architecture/
  README.md
  DEPLOYMENT_GUIDE.md
  netlify.toml
  package.json
  .env.example
```

### 2. Publish the current site with GitHub Pages
In the repository settings, configure Pages to deploy from your main branch and the `/docs` folder. The website is intentionally using hash routes, so GitHub Pages does not need SPA rewrite rules.

At this stage GitHub contains:
- website code
- content JSON
- current images
- the Supabase schema for later

No Supabase connection is required yet.

### 3. Optional: connect the same GitHub repository to Netlify
You can do this immediately or later. Netlify should publish the `/docs` folder. The included `netlify.toml` already specifies that folder and runs the runtime-config generator.

While you are still in local mode, leave the Netlify environment variables as:
```
CONTENT_PROVIDER=local
AUTH_PROVIDER=none
MEDIA_PROVIDER=local
```
The website behaves the same as GitHub Pages.

### 4. When you want real staff admins: add Supabase
Do this only when you want people to log in and change FAQs, Resources or Academy metadata without GitHub.

1. Create a Supabase project.
2. Open its SQL editor and run `/supabase/schema.sql`.
3. Run `/supabase/seed.sql` to copy the current published content into the database.
4. Create staff users in Supabase Auth.
5. After your own account exists, promote it in the SQL editor:
   ```sql
   update public.profiles set role='admin' where id='<YOUR AUTH USER UUID>';
   ```
6. In Netlify environment variables set:
   ```
   CONTENT_PROVIDER=supabase
   AUTH_PROVIDER=supabase
   MEDIA_PROVIDER=local
   SUPABASE_URL=<project URL>
   SUPABASE_PUBLISHABLE_KEY=<publishable key>
   FEATURE_ADMIN=true
   ```
7. Redeploy Netlify.

The public website now reads products/FAQs/resources/Academy metadata from Supabase, but **your existing images can remain in GitHub**. This is a good intermediate hybrid.

### 5. Move images to Supabase only when useful
Do not move every current image just because Supabase exists. Move media when you want staff to upload/replace it from the admin workflow.

Recommended Supabase bucket initially: `support-media`.

After migration, set:
```
MEDIA_PROVIDER=supabase
SUPABASE_MEDIA_BUCKET=support-media
```
New content can use Supabase media URLs. Existing GitHub images can continue working during transition.

### 6. Academy videos: start simple, move to AWS only if needed
Lesson metadata belongs in Supabase from the beginning of the admin phase:
- title
- course
- lesson number
- description
- duration
- video provider
- video URL
- thumbnail

The video file itself can initially be Supabase Storage or another approved platform. If the Academy grows or delivery costs/performance justify it, move video binaries to S3 + CloudFront and set `AWS_PUBLIC_BASE_URL`. Keep the same Academy records and only change `video_provider` / `video_url`.

**Never put AWS access keys, a Supabase secret/service-role key, or other privileged credentials in GitHub or browser JavaScript.** Browser uploads to AWS should eventually use short-lived presigned URLs generated by a trusted server/serverless function.

## Practical migration order
```
NOW
GitHub = code + JSON + images
        ↓
OPTIONAL HOST CHANGE
GitHub → Netlify = deployment only
        ↓
ADMIN PHASE
GitHub/Netlify = frontend
Supabase = Auth + content database
GitHub = existing images
        ↓
MEDIA PHASE
Supabase = new editable images/files
        ↓
VIDEO SCALE PHASE (only if needed)
AWS S3/CloudFront = Academy video delivery
Supabase = lesson metadata + admin/auth
```

This order keeps every step reversible and avoids a big-bang migration.
